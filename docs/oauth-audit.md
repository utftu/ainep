# Проверка клиентского OAuth и строгого шлюза — 2026-11-02

Проверен установленный нативный Claude Code 2.1.281 без патча. SHA-256: `a922981f6f3b55a251ef9f9dbaa0621a5f99cbcb5ca67f8a797476ccfc83f626`.

## Подтверждено локальным запуском

Все восемь сценариев прошли: OAuth из временного сохранённого хранилища, OAuth из переменной окружения, API-key сообщение, Read, resume, safe-mode, Read через шлюз, resume через шлюз. Отчёт: [oauth-audit.json](oauth-audit.json).

`ANTHROPIC_BASE_URL` направляет Messages на custom origin. `ANTHROPIC_CUSTOM_HEADERS` добавляет отдельный `x-gateway-token`; клиентский `Authorization: Bearer` при этом сохраняется. На upstream шлюза проверено точное совпадение с искусственным access token; ключ шлюза не пересылается. metadata сохраняется. Необязательный `/api/hello` отклонялся; это не помешало проверенным сценариям.

OAuth-сценарии используют `--safe-mode`, а не `--bare`: в проверенном bare-запуске OAuth-вариант не дошёл до Messages. Сохранённый OAuth проверялся через временный `.credentials.json` с искусственными access/refresh token и будущим expiresAt. Настоящий Keychain недоступен sandbox, поэтому это не проверка входа в настоящий аккаунт или чтения его Keychain.

Sandbox разрешал только один localhost-порт, запрещал пользовательские каталоги, реальные Keychain-сервисы и запись вне временной папки. Preflight проверял разрешённый/запрещённый порты и запрет чтения искусственного внешнего файла. Интернет-запросы не выполнялись. В отчёте нет значений токенов, идентификаторов или диалогов.

## Обновление OAuth: установлено статически

В бинарнике production `TOKEN_URL` равен `https://platform.claude.com/v1/oauth/token`. Функция обновления `mie` (смещение 175767253 около grant_type) отправляет туда JSON с `grant_type: refresh_token`, `refresh_token`, `client_id`, `scope`. Это отдельный путь от `ANTHROPIC_BASE_URL`.

`CLAUDE_CODE_CUSTOM_OAUTH_URL` проходит проверку встроенного списка из трёх адресов Anthropic. Произвольный VPS не входит в этот список. Простая смена API base URL не направляет refresh или обмен кода авторизации через наш шлюз.

В рамках этой проверки браузерный login, реальный refresh, запись в настоящий Keychain и MITM не выполнялись. Не делаем вывод о невозможности сетевого туннеля: для него нужен отдельный сетевой дизайн и тест. При полном запрете прямого выхода клиент может потерять доступ после истечения токена. Нынешний шлюз обслуживает только Messages и count_tokens, не OAuth endpoints.

## Строгая проверка

Схемы задают ограниченное поддерживаемое подмножество протокола, а не полную копию API. Неизвестные поля протокольных объектов, типы блоков и версии API отклоняются. Для обоих маршрутов используются разные схемы. Проверяются обязательные поля, типы, перечисления, диапазоны числовых параметров, дубликаты JSON-ключей и глубина до 64.

Tool input, схемы инструментов/структурированного вывода, текст и metadata.user_id остаются пользовательскими данными: произвольные ключи внутри input или JSON Schema допустимы. Они не фильтруются как протокольные поля. metadata.user_id остаётся непрозрачной строкой, включая JSON внутри строки.

Сжатие проверяется с лимитом распакованного тела; принятые декодированные байты передаются без повторной сериализации. Это сохраняет идентификаторы, подписи, пробелы и точные числовые литералы в пользовательских данных.

## Ограничения результата

Mock подтверждает работу клиентского цикла, авторизацию шлюза и прохождение схем. Он не подтверждает принятие запросов настоящим Anthropic, все beta-возможности, работу OAuth refresh или соответствие правилам сервиса. Серверные инструменты, PDF/document и неизвестные блоки пока намеренно отклоняются.

Справочные источники: [Messages API](https://platform.claude.com/docs/en/api/messages/create), [авторизация Claude Code](https://code.claude.com/docs/en/authentication). Реализация фиксирует версию заголовка `2023-06-01`, используемую проверенным клиентом, а не автоматически принимает новые редакции API.
