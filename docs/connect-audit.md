# CONNECT-проверка — 2026-11-02

Claude Code 2.1.281, тот же SHA-256, что в provider-audit. Результаты: [connect-audit.json](connect-audit.json).

Стенд записывает искусственный истёкший OAuth во временную папку и задаёт HTTPS_PROXY с фиктивными Basic credentials. На локальном CONNECT listener проверяются ключ и список назначений. Вместо внешней сети openConnection записывает разрешённый hostname и имитирует отказ, поэтому сервер возвращает 502. Sandbox позволяет только локальный mock API и этот CONNECT listener, запрещая прямой выход, реальные credentials и пользовательские файлы.

Наблюдалось `platform.claude.com:443` на прошедшем авторизацию CONNECT-пути. Это подтверждает использование штатным клиентом HTTPS_PROXY при попытке обновления сохранённого токена. Mock API принимает фиктивный токен, поэтому нулевой exit code клиента не является доказательством успешного refresh. Сам обмен токенов намеренно не завершался.

Восемь предыдущих сценариев сообщений/Read/resume также прошли. Первичный браузерный login, настоящий Keychain, реальный аккаунт, редиректы и все служебные API не тестировались. Внешних запросов к Anthropic не было.

Отдельно проверена передача TLS через HTTPS CONNECT: локальный mock upstream с временным сертификатом на platform.claude.com, HTTPS listener прокси с сертификатом на localhost, curl с явным доверием только тестовому сертификату. Успешно передан POST на /v1/oauth/token через внешний и внутренний TLS; проверки сертификатов включены. Proxy-Authorization не дошёл до upstream. Сертификат/ключ и серверы удалены после теста.

Пять автоматических CONNECT-тестов проверяют отказ до соединения при неверном ключе/назначении, запрет обычного HTTP forward proxy, передачу байтов после handshake, отсутствие раскрытия credentials при отказе upstream и обязательный TLS на внешнем listener.

Настройка HTTPS_PROXY маршрутизирует клиент, но не устанавливает firewall и не меняет прокси браузера. Эти действия не выполнялись.
