# ainep

Шлюз запросов к AI-провайдерам с отдельными маршрутами и закрытыми схемами. Первый реализованный провайдер — Claude на `/claude`: передаёт клиентский OAuth Bearer к фиксированному upstream. Credentials остаются под управлением клиента; шлюз видит access token в памяти при обработке запроса, но не хранит его и не обновляет. Это не средство гарантированной анонимности или предотвращения блокировок.

## Установка npm-пакета

Подготовлена версия 0.3.0; она ещё не опубликована в registry. Требуется установленный Bun >=1.3.0 в PATH: Node.js сам по себе недостаточен.

После публикации:

```sh
bunx ainep
bunx ainep --help
bunx ainep --version
```

Для глобальной установки: `npm install -g ainep` или `bun add -g ainep`. Команда `ainep` без аргументов запускает сервер с переменными окружения, описанными ниже. Bun читает `.env` из рабочей папки; запускайте сервер из отдельной папки с его конфигурацией. CONNECT-прокси запускается отдельной командой `ainep connect`; OAuth по-прежнему обновляет сам клиент.

Локальную упаковку можно проверить до публикации:

```sh
npm pack --dry-run
npm pack
```

`prepack` запускает проверку типов, тесты и сборку. В npm-архив включаются только `dist/ainep.js`, package.json, README и файл лицензии, если он добавлен. Исходники, тесты, отчёты, `.env`, сертификаты и декларации внутренних модулей не публикуются. Зависимости desy/h11 устанавливаются npm отдельно и не встроены в сборку.

## Сервер

Нужен Bun 1.3.0 или новее:

```sh
bun install --frozen-lockfile
```

В `.env` с правами 600 задать только отдельный ключ доступа к шлюзу:

```dotenv
GATEWAY_TOKEN="заменить-случайным-ключом"
```

Ключ должен содержать минимум 32 печатных ASCII-символа без пробелов. Генерация: `openssl rand -hex 32`. Файл `.env` исключён из git. `ANTHROPIC_AUTH_TOKEN` на сервере больше не используется; старое серверное значение следует убрать из своего окружения/хранилища при миграции. Программа не читает Keychain.

```sh
bun start
```

По умолчанию listener `http://127.0.0.1:8443`. Для внешнего listener задать `GATEWAY_HOST`, `GATEWAY_PORT`, `TLS_CERT_FILE`, `TLS_KEY_FILE`. Без TLS внешний listener запрещён; проверку TLS upstream отключать нельзя. Сборка: `bun run build`, запуск: `bun dist/ainep.js`.

## Клиент и авторизация

Для запуска через launcher задайте на Mac адреса уже работающих серверов и общий ключ в окружении или `.env` с правами 600:

```dotenv
GATEWAY_URL=https://your-gateway.example:8443
CONNECT_PROXY_URL=https://your-gateway.example:8444
GATEWAY_TOKEN="заменить-ключом-сервера"
```

Адреса — origin без `/claude`, имени пользователя и пароля. Для локального запуска допустимы `http://127.0.0.1:8443` и `http://127.0.0.1:8444`; вне loopback требуется HTTPS.

```sh
ainep run claude
ainep run claude --resume
```

Из исходников: `bun src/proxy/main.ts run claude`; после сборки: `bun dist/ainep.js run claude`. Штатный Claude Code должен быть установлен в PATH. Launcher передаёт аргументы без shell, рабочую папку, stdin/stdout/stderr и код завершения; SIGINT/SIGTERM/SIGHUP передаются клиенту. API-сервер и CONNECT-сервер он не запускает.

Настройки применяются только к дочернему процессу: launcher добавляет `/claude`, задаёт `ANTHROPIC_CUSTOM_HEADERS` с ключом шлюза, формирует proxy URL с кодированным паролем. Заменяет верхний и нижний регистр HTTP_PROXY/HTTPS_PROXY/ALL_PROXY и NO_PROXY; bypass содержит только hostname API-шлюза и loopback. Прежние custom headers заменяются целиком. Остальное окружение, включая клиентскую авторизацию, наследуется. Ключ доступен дочернему клиенту в его окружении; launcher его не печатает и не сохраняет.

Команда не устанавливает alias `claude`, не меняет shell-конфигурацию и не блокирует прямую сеть средствами ОС. Настройки HTTPS_PROXY могут ограничивать сетевые инструменты/MCP тем же списком хостов CONNECT. Проверки launcher выполнены с искусственным клиентом; реальный OAuth login/refresh этим не подтверждён.

Схема для проверенного custom API origin:

```text
ANTHROPIC_BASE_URL=https://<домен-шлюза>/claude
ANTHROPIC_CUSTOM_HEADERS=x-gateway-token: <отдельный-ключ-шлюза>
```

Это обозначения настроек, а не готовые секреты или инструкция извлечения токена из Keychain. Штатный OAuth access token клиент добавляет в `Authorization: Bearer`; шлюз передаёт его без подмены. Сам `x-gateway-token` остаётся на шлюзе. `x-api-key`, отсутствие или неоднозначность credentials отклоняются. В серверной конфигурации upstream OAuth отсутствует. Ротация клиентского access token не требует перезапуска шлюза.

Тест с временным сохранённым OAuth и тест с `CLAUDE_CODE_OAUTH_TOKEN` прошли на mock в режиме safe-mode. Реальный Keychain и аккаунт не использовались. `--bare` не является проверенным OAuth-сценарием.

Обновление OAuth можно направить через отдельный CONNECT-прокси `ainep connect` с помощью `HTTPS_PROXY`. Сам сервер не обновляет и не хранит OAuth. Проверена попытка refresh штатного клиента через прокси с фиктивным токеном и искусственным отказом upstream; полноценный вход в реальный аккаунт не выполнялся. Настройки ниже.

## HTTP и поддерживаемая схема

Только POST `/claude/v1/messages` и `/claude/v1/messages/count_tokens`, необязательный одиночный `?beta=true`. Content-Type — application/json. Поддерживаемая версия `anthropic-version: 2023-06-01` (используется и по умолчанию). Остальные версии отклоняются. Префикс `/claude` снимается перед отправкой: upstream получает `/v1/messages` или `/v1/messages/count_tokens`. Старые маршруты `/v1/...` без префикса и неизвестные провайдеры возвращают 404. Origin провайдера Claude всегда `https://api.anthropic.com`; пользователь не может выбирать адрес назначения. Редиректы не выполняются и возвращаются как 502 без Location.

Поддерживаемое подмножество описано desy 0.0.29 в `src/providers/claude/schema.ts`:

- Оба маршрута: model, messages; optional system, tools, tool_choice, thinking, context_management.
- Messages дополнительно требует max_tokens; допускает metadata.user_id, stream, temperature, top_p, top_k, stop_sequences, service_tier, cache_control, output_config.
- Блоки: text, image (base64/url), thinking, redacted_thinking, tool_use, tool_result. В tool_result — строка или text/image блоки.
- Инструменты: пользовательские JSON Schema, strict/defer_loading/cache_control. Серверные инструменты и document-блоки пока не поддерживаются.
- Context management: только clear_thinking_20251015. Другие варианты отклоняются до добавления схемы и тестов.

Неизвестные поля во вложенных протокольных объектах и неизвестные типы блоков дают 400 без отправки upstream. Tool input, input_schema и output_config.format.schema являются пользовательскими данными с произвольными ключами; строки, включая metadata.user_id, не проверяются на отсутствие личных данных. Это контроль формата, не фильтр содержимого. Beta-заголовок передаётся; это не обещание поддержки всех beta-функций. Неизвестные входящие заголовки не пересылаются.

metadata сохраняется: прежнее удаление отменено. Всё принятое JSON-тело сохраняется побайтно после распаковки, без повторной сериализации. Разбор выполняется JSON.parse: при дублировании ключа проверяется последнее значение. Отдельного лимита глубины нет. Проверка структуры не заменяет все семантические ограничения сервера Anthropic.

Поддерживаются identity, gzip, deflate (zlib), br. Неизвестная/составная кодировка — 415, повреждённое сжатие или UTF-8/JSON — 400, превышение 16 MiB до/после распаковки — 413. Проверка распакованного лимита выполняется внутри декомпрессора.

Входящие cookies, forwarding-заголовки и заголовки SDK не копируются. Из ответа передаются content-type, request-id, retry-after, anthropic-ratelimit-*; cookies и Content-Length/Content-Encoding не копируются. Ошибки upstream, включая 401/429, получает клиент. Повторов и OAuth refresh на сервере нет.

Deadline 10 минут, включая SSE; idleTimeout 60 секунд. При отключении клиента upstream отменяется. После начала SSE ошибку передают обрывом потока, поэтому клиент должен проверять завершающее событие. Журнал содержит только provider/route/status/durationMs до начала ответа; тела и credentials в журнал не попадают.

## Проверка

```sh
bun test
bun run check
bun run build
bun run audit /absolute/path/to/claude docs/provider-audit.json
```

44 автоматических теста: авторизация и смена клиентского токена, закрытые схемы, отсутствие upstream-вызовов при отказе, сжатие, лимиты, точность тела, защита адреса назначения, SSE и отмена, окружение launcher, передача аргументов/stdio/кода завершения и сигналов.

Восемь сценариев настоящего клиента повторно прошли с префиксом `/claude`: [docs/provider-audit.json](docs/provider-audit.json). Методика и ограничения описаны в [docs/oauth-audit.md](docs/oauth-audit.md). Стенд использует отдельные временные config/tmp/cwd, фиктивные credentials и sandbox с единственным разрешённым localhost-портом. Настоящие credentials, настройки пользователя и диалоги недоступны. Preflight проверяет изоляцию до запуска Claude; временные файлы удаляются. Реальный вход/refresh и весь сетевой трафик обычного клиента этим не проверены.

Прокси сам по себе не блокирует прямую сеть клиента. Развёртывание на VPS и правила macOS ещё не выполнены. Аудиты [docs/audit.md](docs/audit.md) и [docs/client-audit.md](docs/client-audit.md) описывают предыдущую реализацию; актуальные решения — [docs/decisions.md](docs/decisions.md).

## Модули провайдеров

Общий транспорт в src/proxy отвечает за ключ шлюза, TLS, лимиты, timeout и потоки. Общая обработка тела в src/privacy распаковывает JSON и вызывает переданную провайдером проверку.

src/providers/provider.ts определяет контракт: id, фиксированный origin, точные входящие и upstream-маршруты, проверка запроса/тела, исходящие заголовки и заголовки ответа. src/providers/claude содержит реализацию Claude и его desy-схемы. Другие провайдеры пока не реализованы.

Переход на 0.2.0 требует добавить `/claude` к ANTHROPIC_BASE_URL. Клиентский ключ x-gateway-token и OAuth Bearer остаются прежними.

## Авторизация через VPS: CONNECT-прокси

Запустите на VPS два процесса. HTTPS-сертификат и ключ доступа у них могут быть общими; порты должны отличаться:

```sh
GATEWAY_PORT=8443 ainep
GATEWAY_PORT=8444 ainep connect
```

Для внешнего listener задайте GATEWAY_HOST=0.0.0.0, GATEWAY_TOKEN, TLS_CERT_FILE и TLS_KEY_FILE в окружении или .env. Обе команды требуют Bun. При работе из исходников замените `ainep` на `bun src/proxy/main.ts`, после сборки — на `bun dist/ainep.js`.

На Mac задайте перед запуском Claude Code (значения в угловых скобках замените своими):

```sh
export ANTHROPIC_BASE_URL="https://<домен-VPS>:8443/claude"
export ANTHROPIC_CUSTOM_HEADERS="x-gateway-token: <ключ-шлюза>"
export HTTPS_PROXY="https://ainep:<ключ-шлюза-в-URL-кодировке>@<домен-VPS>:8444"
export NO_PROXY="<домен-VPS>,localhost,127.0.0.1"
```

Ключ из `openssl rand -hex 32` не требует URL-кодировки. Имя пользователя CONNECT-прокси строго `ainep`, пароль — GATEWAY_TOKEN. NO_PROXY относится к адресу назначения: запросы к нашему API-шлюзу идут прямо на VPS, а внешние HTTPS-соединения клиента — через CONNECT. Если уже установлены lowercase `https_proxy`, `http_proxy` или `no_proxy`, уберите конфликтующие значения перед запуском: они могут иметь приоритет.

Разрешённые CONNECT-назначения: platform.claude.com:443, claude.ai:443, claude.com:443. Прочие домены, IP, порты и прямой api.anthropic.com запрещены. Обычный HTTP forward proxy не поддерживается. Неподходящие credentials дают 407, запрещённое назначение — 403, отказ upstream — 502. При отказе не предусмотрен прямой fallback внутри ainep.

Прокси не расшифровывает внутренний TLS, не читает URL-путь или OAuth-токены. Это разрешение соединений с хостами, а не проверка только `/v1/oauth/token`. Proxy-Authorization заканчивается на прокси и не передаётся upstream. Не создаётся открытый прокси: обязательны credentials и фиксированный список назначений. HTTPS до самого VPS защищает ключ прокси; plaintext допускается только на loopback для тестов.

Соединение с upstream ограничено 10 секундами, idle-туннель закрывается через 60 секунд; число одновременно отслеживаемых сокетов ограничено. Произвольные назначения, в том числе сетевые обращения некоторых инструментов/MCP, с этим HTTPS_PROXY будут отклоняться. Не расширяйте NO_PROXY на Anthropic для обхода ошибок: сначала проверьте требуемый маршрут.

Настройки применяются к Claude Code, а не автоматически к браузеру входа. Сеть браузера настраивается отдельно. Эта версия не устанавливает firewall на Mac и не развёртывает сервисы на VPS. Строгий запрет прямого выхода средствами ОС — отдельный шаг.

Проверка: [docs/connect-audit.md](docs/connect-audit.md). Успешный обмен/ротация реального OAuth и все вспомогательные маршруты первого входа ещё не проверены; некоторые могут требовать отдельного решения маршрутизации без открытия прямого API.
